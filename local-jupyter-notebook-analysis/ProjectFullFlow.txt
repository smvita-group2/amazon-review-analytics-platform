PROJECT OBJECTIVE
===========================================================================================

Develop a production-ready Product Intelligence Platform capable of processing
large-scale Amazon Product Review datasets using Apache Spark on AWS while
providing Business Intelligence and AI-powered Product Search through a
single unified web application.

The platform should follow modern Data Engineering practices and production
software engineering standards.

The final platform should support

✓ Distributed Data Processing

✓ Exploratory Data Analysis (EDA)

✓ Business KPI Generation

✓ Interactive Business Dashboards

✓ AI Powered Semantic Product Search

✓ Automated ETL Pipelines

✓ Cloud Deployment

✓ CI/CD

✓ Production Monitoring

The objective is not just to analyze data.

The objective is to build a complete Product Intelligence Platform.



===========================================================================================

PROJECT PHILOSOPHY

===========================================================================================

The project consists of TWO completely different systems working together.

──────────────────────────────────────────────────────────────────────────────

SYSTEM 1

DATA ENGINEERING PLATFORM

Responsible for

• Data Validation

• Data Cleaning

• Data Transformation

• Data Integration

• Exploratory Data Analysis

• KPI Generation

• Feature Engineering

• Semantic Dataset Preparation

• Embedding Generation

Runs using

Apache Spark

Amazon EMR

AWS Glue

Amazon S3

──────────────────────────────────────────────────────────────────────────────

SYSTEM 2

APPLICATION PLATFORM

Responsible for

Providing ONE interface to the user.

The application contains TWO modules.

Module 1

AI Product Search

(Chatbot)

Module 2

Business Analytics Dashboard

(Tableau Embedded)

Both modules are accessed from ONE Streamlit application.

The user should never interact with two separate applications.

Everything should feel like one unified Product Intelligence Platform.

SCRIPTS DIRECTORY
===========================================================================================

Purpose

Contains executable entry points.

Business logic always lives inside

Structure

scripts/

│

├── local/

Runs during local development.

Reads local datasets.

Validates notebook logic.

────────────────────────────────────

emr/

Runs on Amazon EMR.

Reads from S3.

Writes to S3.

Distributed Spark execution.

────────────────────────────────────

glue/

Runs as AWS Glue Jobs.

Uses same processing logic.

Only execution environment changes.

Example

scripts/emr/bronze_to_silver.py

↓

imports

↓

src/data_pipeline/processing/bronze_to_silver.py

Exactly the same processing module should also be imported by

scripts/local/

scripts/glue/

This guarantees

✓ Single codebase

✓ No duplicated logic

✓ Easier maintenance

✓ Same output everywhere

PROJECT DEVELOPMENT STANDARDS
===========================================================================================

The objective of this guide is to ensure that every team member follows the
same engineering standards throughout the project.

Every notebook

Every production script

Every dashboard

Every documentation update

should follow these standards.

A consistent codebase is easier to understand, maintain and extend.


===========================================================================================

CODING STANDARDS
===========================================================================================

General Rules

✓ Write clean and readable code.

✓ Keep functions small and modular.

✓ Avoid duplicate logic.

✓ Use descriptive variable names.

✓ Use descriptive function names.

✓ Write reusable code.

✓ Add comments only when necessary.

✓ Follow a consistent coding style.

✓ Keep notebooks organized.

✓ Keep production code independent of notebooks.


Never

❌ Hardcode paths

❌ Hardcode bucket names

❌ Hardcode credentials

❌ Duplicate business logic

❌ Mix visualization logic with semantic logic

❌ Read Bronze after Silver exists

❌ Read Raw directly for downstream processing
